# 微信支付接入与商户开通指南

更新：2026-11-13。项目：`E:\workspace\idea-notes`。

## 当前状态

已完成微信支付 API v3 **普通商户直连**代码：Native 扫码、可选 H5、服务端下单与价格快照、订单查询、支付回调验签解密、手动续费、权益发放、关闭订单、整笔原路退款、支持请求和后台审计。

目前没有商户账号，未配置密钥或正式价格，**真实收款未启用**。本次没有注册商户、提交资质、创建真实订单或发生扣款。后端测试使用本地 RSA 签名和 AES-GCM 加密的模拟微信接口；浏览器支付流程使用测试拦截，模拟二维码不可支付。这不是微信官方沙箱验收，不能替代开通后的实单联调。

## 先申请什么

1. 准备适用的经营主体。微信官方 Native 接入文档列出的主体包括个体工商户、企业、事业单位、政府机关、社会组织。普通个人微信收款码不等同于可调用本项目接口的商户号。如果目前只有个人身份，需要先确认适用主体和资质，再按官方流程申请。
2. 申请微信支付商户号，并开通 **Native 支付**。按官方指引填写实际服务内容、经营场景、域名及相关备案/授权资料，是否获批以微信审核为准。
3. 准备受支持、已认证的 APPID，并与商户号完成绑定授权。PWA 不需要重写成小程序，但 API 下单仍需要符合要求的已绑定 APPID。
4. 手机浏览器需要直接跳转微信付款时，再申请 **H5 支付**并配置支付域名。Native 二维码供另一台设备的微信扫一扫使用，不支持依赖长按或相册识别付款。
5. 准备公网 HTTPS 域名。`localhost:3001` 仅供本机预览，微信无法回调你的 localhost。

## 开通后填写哪些配置

配置写入项目 `.env` 或部署平台的密钥管理器。密钥文件不要发到聊天、放进前端或提交 Git；项目已忽略 `secrets/`、`.pem`、`.p12`、`.pfx`。

| 配置                                   | 内容                                                 |
| -------------------------------------- | ---------------------------------------------------- |
| `WECHAT_MCH_ID`                        | 审核通过的商户号                                     |
| `WECHAT_APP_ID`                        | 与商户号绑定的 APPID                                 |
| `WECHAT_SERIAL_NO`                     | 商户 API 证书序列号，不是微信支付公钥 ID             |
| `WECHAT_PRIVATE_KEY_PATH`              | 商户 API 证书私钥 `apiclient_key.pem` 的本地路径     |
| `WECHAT_PUBLIC_KEY_ID`                 | 微信支付公钥 ID，通常以 `PUB_KEY_ID_` 开头           |
| `WECHAT_PUBLIC_KEY_PATH`               | 从商户平台获取的微信支付公钥文件路径                 |
| `WECHAT_API_V3_KEY`                    | 32 字节 APIv3 密钥，用于解密回调                     |
| `WECHAT_NOTIFY_URL`                    | `https://你的域名/api/payments/wechat/notify`        |
| `WECHAT_REFUND_NOTIFY_URL`             | `https://你的域名/api/payments/wechat/refund-notify` |
| `WECHAT_H5_ENABLED`                    | H5 开通且域名配置完成后设为 `true`，默认 `false`     |
| `STANDARD_PRICE_FEN` / `PRO_PRICE_FEN` | 正式月费，**整数人民币分**；没有默认售价             |
| `STANDARD_POINTS` / `PRO_POINTS`       | 每订阅月点数，默认联调值 2000 / 6000                 |
| `PAYMENT_SUPPORT_EMAIL`                | 实际处理订单问题的客服邮箱                           |
| `PAYMENT_REFUND_POLICY_URL`            | 已确定并发布的 HTTPS 退款政策页面                    |
| `APP_ORIGIN`                           | 实际公开的 HTTPS 源地址，不含末尾斜杠或路径          |
| `PAYMENT_ENABLED`                      | 默认 `false`；商户、定价、政策与联调准备完成后才启用 |
| `PAYMENT_REFUNDS_ENABLED`              | 默认 `false`；需要在后台执行真实退款时单独启用       |

本实现采用微信官方推荐的**微信支付公钥**验签模式，不自动信任未知平台证书。更换公钥必须同步更新可信公钥 ID 和公钥文件；旧通知验签失败时可依靠服务端查单恢复。

真实收款模式要求 `NODE_ENV=production`、`AUTH_MODE=smtp`、真实 AI 配置和 HTTPS。开发验证码及演示 AI 不允许直接启用真实收款。退款只有已授权管理员可操作，必须填写原因并明确确认。正式部署仍应补齐管理员强认证。

## 部署与回调

- 同域反向代理前端与 `/api`，保持签名回调原始请求体。两个回调在 JSON 解析和浏览器 CSRF 检查之前独立验证微信签名，其他写接口仍需会话及来源校验。
- 开放两个 HTTPS 通知地址，不能跳转登录页、附加查询参数或重写消息体。服务器时间需同步，签名时间窗为 5 分钟。
- H5 的 `payer_client_ip` 来自服务端可信连接。代理后配置 `TRUSTED_PROXY_CIDRS` 为实际代理 IP/CIDR，并在代理层覆盖不可信转发头。不要信任任意公网客户端的 `X-Forwarded-For`。
- H5 支付域名与回跳域名必须符合商户平台配置。链接使用 `referrerPolicy="origin"`，避免默认 no-referrer 导致域名校验问题；仍需真机验证 Safari、Android Chrome 和独立 PWA。微信内置浏览器引导至系统浏览器；本版没有 JSAPI / OpenID OAuth。
- Native 订单有效期 30 分钟；H5 URL 有效期 5 分钟，可用同一订单重新获取。前端不可生成新订单来跳过旧订单核对。
- 返回参数 `payment_order` 仅定位订单，后端查单才确认支付；前端成功页不能自行发放权益。

## 数据与业务规则

- 数据库迁移 v2 新增套餐快照、订单、订阅和回调收据，不重建已有想法。
- 金额来自服务端配置，客户端只提供套餐版本与幂等键，不接受金额字段。改价生成新版本，旧订单保留原价及权益。
- 同账号最多一笔未确认订单，可提前购买一个下一周期。按北京时间日历月计算，31 日跨短月后保留原始锚点。
- 首次付费从权益激活开始；续费从上一周期结束开始，到新周期才发额度。回到免费后复用当月免费账本，不重复领取。
- 核对商户号、APPID、订单号、金额、币种、交易号，再在事务中发放权益。通知、查单与退款均按已有终态去重。
- 退款处理中保留原权益；退款成功才撤销该订单剩余权益。退款未来续费不影响当前周期；已有未来续费时需先处理未来订单，再退款当前周期。
- 跨周期 AI 请求结算原周期预占，不从新周期扣点；已用额度不会形成负余额。
- 有支付记录的账号不再直接走原注销删除流程，需联系支持先处理服务期、退款和交易记录保留。正式运营仍需补齐可追踪人工注销与法定保留策略。

## 查单、异常和退款

用户在“订阅与额度 → 我的订单”查询、关闭未支付订单或提交支持请求。管理员在“管理后台 → 微信支付与订单”查看配置缺项、查单和退款。后台不显示想法正文或密钥。

API 进程每 30 秒扫描任务，每轮最多 20 个订单；付款后台查单通常至少间隔 60 秒，用户查询限速；退款查询至少间隔一分钟。重启后继续从数据库未确认状态查单。已关闭订单后来收到可信成功通知仍会核对；周期冲突时进入“异常待核对”，不重复发权益，可原路退款。

网络超时、签名不可信或金额不符都不会标记支付成功。未签名的错误响应也不能作为已关闭/失败的可信凭据，订单保留待确认，需重试查询或由管理员核实。审计只保存订单编号、原因与错误代码，不保存完整支付通知或付款人身份数据。

当前为**单 API 进程**内置查单任务，尚未提供每日微信交易账单下载对账、独立可靠队列、跨实例任务租约或资金异常告警。外部商户平台发起的退款需要人工核对退款编号，不自动猜测。不要把本地测试视为生产对账已完成。
